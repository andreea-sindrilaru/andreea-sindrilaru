### 🔬 Currently researching

I'm currently working on my **Master's thesis at Eindhoven University of Technology**:

> **Practices and Guidance for Managing Breaking Changes in Java Libraries**

I'm investigating how maintainers of open-source Java libraries deal with changes that can break downstream users.

Some of the questions I'm exploring are:

- How do maintainers discover that a change might be breaking?
- What do they do once a potential breaking change is identified?
- What compatibility guidance or policies exist within projects?
- How are those expectations communicated or enforced?
- Do the practices we observe in repositories align with the project's documented guidance?

The research combines **software repository mining**, analysis of GitHub issues and pull requests, **static analysis**, and **semi-structured interviews with open-source maintainers**.

What I enjoy most about the thesis is that it combines two things I'm naturally drawn to:

**software engineering + investigation.**

It gives me the opportunity to look beyond the code itself and understand the decisions, conventions, trade-offs, and people behind software evolution.
